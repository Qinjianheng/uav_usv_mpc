# 后续 MPC 开发范围

MPC 尚未实现。当前 MINCO 规划、tracker 和 PX4 Offboard 输出构成可运行对照，本轮保持其源码、测试、完整配置、模型与补丁。

后续先定义 MPC 的状态、输入、执行周期和约束，再选择求解器及新增依赖。优先在 `src/uav_control/uav_control/controllers/` 增加独立求解模块，由显式配置选择；需要独立 ROS 节点时沿用现有进程隔离和单一 PX4 指令发布者约束。现有接口由 [uav_usv_interfaces](../../src/uav_usv_interfaces/msg) 提供，当前控制入口见 [架构](architecture.md)。

第一阶段使用冻结数据离线回放/影子计算，比较轨迹与指令可行性、求解耗时和失效行为；第二阶段经明确授权接入在线控制并与原控制器做同条件对照。MPC 状态来自 PX4 原始导航与视觉/KF/BCTRA，真值仅作评价，不能用它在线纠偏。

验收必须保留图像采集戳、因果等待/超时拒绝和原始导航 sample epoch；明确状态/预测/指令时刻。保持 0.50 m 捕获半径、海面/机体净空、速度/加速度限制和 freshness，记录不可行、超时、失锁及恢复行为。不得用固定坐标偏置、经验延迟、盲调 KF Q/R 或放宽捕获球掩盖问题。

每次只改一个主要环节，先过现有回归与离线分析，再验证在线效果。新实验默认留在忽略目录；挑选可复算证据后放入新的基线子目录，不能覆盖 [pre_mpc 包](../../data/baselines/20261006_pre_mpc/README.md)。
