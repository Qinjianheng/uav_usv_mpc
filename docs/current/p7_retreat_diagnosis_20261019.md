# P7 八字近场退让原因分析（2026-10-19）

本次只分析上一轮恒速、变速八字的原始日志与冻结源码，没有修改控制器、运行配置或重新仿真。

近场退让直接由纵向视场保护发起。其幅度和持续时间又被速度指令积分、实际速度响应、升沉高度参考和水平对准门控共同放大。两轮始终保持 P7_GUIDANCE/FAR_GUIDANCE，全部诊断样本的 visible/locked 均为真；这次距离增大不是失锁进入恢复，也不是 MINCO 接管失败。

“退让”是相对 USV 拉开距离。退让窗口内，发出速度沿 KF 目标运动方向的投影最小仍为恒速 2.957 m/s、变速 1.668 m/s，不能解释成 UAV 在世界坐标中原地倒飞。

## 直接触发条件与实测时序

`p7_visual_guidance.py` 使用原始图像采集戳计算纵向误差变化率，并保持重复图像戳的最近变化率：

```text
g = e_v + max(0, de_v/dt) / 1.2
若 g > 0.7：
    desired_closing = min(已有闭合请求, max(-0.75, 0.6 * (0.7-g)))
```

`e_v` 为向画面下方的归一化误差；`1/1.2 = 0.833 s` 来自控制增益对应的响应尺度，不是测得的传感器延迟。此条件可以在当前目标中心尚未到下缘时请求负闭合速度。固定相机不能独立转动，退让意图是避免继续从下缘出画。这条启发式保护本身没有给出完整球体的视场安全证明。

## 为何发生明显往复

1. **期望减速没有及时转化为实际减速。** 水平距离刚进入 1 m 时，恒速轮实际闭合速度为 0.794 m/s，期望已降到 0.404 m/s；变速轮分别为 0.663 / 0.399 m/s。视场保护发起时仍存在明显速度差。保护触发到实际转为远离相隔约 1.15 / 1.05 s；这段间隔包括当时的减速过程，不能直接当作固定执行延迟。两轮接受的图像年龄约 50–54 ms，未触发输入陈旧或失锁恢复，不能把约一秒的运动响应归因成一秒图像延迟。

2. **限幅的“闭合请求”没有直接限制最后发出的相对速度。** 捕获阶段计算 `a = 1.2 * (v_target + closing * direction - v_actual)`，再将加速度积分到上一条速度指令；目标速度变化还通过前馈进入。指令有水平速度/加速度总限幅，但没有以 `closing` 为中心的相对径向输出限幅。实际响应跟不上时，积分状态继续积累减速量。首次退让中，期望退让最低 -0.75 m/s，发出指令相对于同一 KF 目标、同一视线方向的径向投影却最低达到 -1.019 / -0.881 m/s；实际相对速度最低达到 -0.819 / -0.831 m/s。这里没有违反世界坐标总速度限制，但说明“0.75”不能当作最终相对退让速度上限。

3. **升沉参考使近场水平间距重新打开。** `capture_reference()` 的水平参考是 `min(4.5, 0.30 + 2 * remaining_descent)`，其中高度参考又是 `min(target_z-0.33, sea_z-0.33)`。艇体升沉周期为 4 s。靠近波峰时 UAV 被参考带着上升，随后目标下降、UAV 尚未降到新的接触高度，`remaining_descent` 增大；首次退让窗口的 standoff 最大达到 0.554 / 0.576 m。单独保留深度/高度间距项、去掉图像门控，在这批相同记录输入上最低也会要求 -0.074 / -0.078 m/s 的轻微远离；图像保护再把它放大到 -0.75 m/s。此为记录输入上的代数消融，不是去掉保护后真实飞行会成功的证明。

4. **水平对准门控延长了重新接近的等待。** 当 `abs(e_u)>0.15` 时，正闭合请求被置为零。纵向保护释放后，两轮又分别等待约 0.75 / 0.80 s 才允许正闭合请求。这时实际已经远离，速度指令和飞机还需再次响应，因此距离峰值更晚出现。这是门控叠加，不是任务状态来回切换。

## 图像向下运动的几何来源

对 UAV/红球使用完全相同 Gazebo 原生位姿戳，采用完整姿态、相机真实平移外参 `(0.18, 0, 0.39)`、28° 下倾和红球中心位置复算；原生时间仅在同消息 Clock 的 ≤50 ms 有效括号内映射，拒绝外推。该几何只作离线评价。

从首个视场制动附近到首轮几何纵向误差峰值，使用对称有限差分分解每一步变化，合计结果如下。姿态项包含完整 roll/pitch/yaw 和随姿态旋转的相机杆臂，不能单独称为 pitch 贡献：

| 对原生相机纵向误差变化的贡献 | 恒速 | 变速 |
|---|---:|---:|
| 水平相对位置变化 | +2.6645 | +1.3387 |
| UAV 高度变化 | -0.0408 | +0.0758 |
| 目标升沉 | +0.1853 | +0.1088 |
| 完整机体姿态与相机杆臂 | +0.1202 | +0.0779 |
| 总变化 | +2.9292 | +1.6013 |

这两个限定窗口内，水平间距继续缩短贡献最大；艇体升沉和制动抬头等姿态变化进一步加重。高度不是保持到位后再接近，而是在近场随升沉变化；相机向前安装且位于机体上方，极小水平间距下的投影变化非常快。保护触发后，相机目标仍继续下移，说明现有深度收敛和速度响应不足以维持整个进近过程的视场余量。图像检测仍可利用部分红球拟合中心，故锁定有效不等于中心或整个球始终在画面内。

该分解只描述这两段记录轨迹的几何贡献；不同因素有非线性交互，采用对称分配，百分比不是普适因果权重，也不是新的闭环实验。

## 首轮接触判定还存在独立边界

恒速轮首次进近有 **6 个同原生位姿时刻的三维距离采样 ≤0.50 m**，最小 0.470656 m；第一条发生在 Y+15.910316 s，Gazebo sim=61.740 s。期间没有 `capture_result`，仿真继续，直到第二次接近才结束。变速轮首次进近原生最小距离为 0.531437 m，没有达到半径。

因此，不能把恒速全部往复都解释成“还未接触，所以正常退让”，也不能沿用“首次进近没有命中半径”的表述。控制保护确实发起了退让；恒速轮同时存在评价终态没有覆盖到已记录入径采样的问题。

当前 evaluator 以 20 Hz 定时查询最新共同原生位姿，只在原生间隔 ≤50 ms 时保留相邻样本的线段判定；它没有消费每条原生位姿的完整待评价队列。目标通过离散 `set_pose` 移动，恒速轮的距离曲线有明显锯齿，短暂入径可能落在定时评价的两个接纳点之间，或被严格时间括号拒绝。**缺少每次 evaluator 查询及拒绝的完整日志，现有证据尚不能确定这 6 条具体漏在何处。** 源码支持该采样缺口的可能性，不能把采样相位或某条时间拒绝直接宣称为已证实的唯一原因。

原生位姿与 PX4 导航估计的机体参考不能直接混用；这里没有拟合固定位置偏置、改时间戳或扩大半径。此前两轮最终捕获与暂停的事实保留，但“第一次进近是否入径”必须按本次复查修正。

## 下一步修复优先级

先针对单一的“近场闭合响应与视场约束不协调”建立离线回放边界用例：约束实际闭合状态与已积累的速度指令，结合下降能力、升沉参考和完整相机几何提前安排减速；将水平对准与纵向视场需求协调，避免依靠近场大幅负闭合速度补救。保留视场保护、海面保护、原始采集戳和 0.50 m 半径。不能仅删除退让分支或放宽阈值来掩盖往复。

评价终态作为独立问题处理：先记录每次原生查询的输入时刻/括号/拒绝理由，用同刻原生历史离线回放定位；随后验证有界历史队列能否覆盖每个有效入径样本。该评价只结束仿真，不进入导航、KF 或控制反馈。本次没有实施这些控制/评价修改，也没有新增飞行。
