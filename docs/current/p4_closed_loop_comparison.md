## 负载和规划时延

CPU为本任务所属所有进程累计，一个核心=100%，RSS为进程RSS求和（共享页可重复计数），包括PX4/Gazebo/ROS和评价监测，非算法独占。P50/P95 CPU A=207.59/225.66%，B=253.47/277.64%，八字=276.44/300.12%；RSS P95约1143.9/1264.8/1262.5 MiB。原20Hz reference P50约50ms，稳定窗口P99约52.50/52.64/51.21ms；采样的是监测接收间隔，不能替代PX4执行器响应延迟。

全部提案缺持有和首次桥接。现场clock_generation因各节点独立启动计数(1 vs 0)不一致而拒绝，不能通过抄提案generation消除；需后续接收端拥有的epoch/boot复位同步。预测版本变化拒绝95/150次，说明预测更新经常与规划完成交错，未来应对新预测完整重验而非删除版本门禁。现场另有浮点大epoch编码导致INVALID_INTERVAL=15/26、TTL_EXTENSION=4/11；修复采用sec和fraction分开编码，333原事件离线重编码全部消除这两类假阳性，仅剩正确未持有拒绝。该复算不是新的现场接纳实验。

## 上游延迟与预测时域

新八字同轮测量：图像→接收P95=31.96ms、接收→处理9.73ms、处理→发布0.048ms、发布→预测生成2.23ms、预测Python计算3.02ms、图像→预测接收43.76ms。各分位不能相加作为端到端分位。因果pose等待和仿真接收调度仍是端到端的一部分；未调Q/R或加经验延迟。

同一未来真值覆盖人群466条、原生Gazebo运动离线评价：H=0.8/1.2/1.6/2.4/4 s预测水平RMSE为0.495/0.667/0.852/1.356/3.584 m，P95为0.765/1.107/1.541/2.649/7.406 m。包含KF当前估计误差，不是纯运动模型误差，更不是误差保证。该机动下短前缀有意义；滚动更新能缩短依赖的未来区间，但不消除采集/因果等待时延，也不能自动证明实际跟随改善。

## 故障、权限与清理

三轮成功仿真所有已发现的3个PX4控制输入话题均唯一trajectory_tracker_node发布者，计数A93/109、B93/109、八字119/135，余下为发现前/结束期间，冲突0。B在有界会话内向确认PID/start身份的本任务研究子节点发SIGINT，之后496条原reference继续，最大间隔56.52ms；这验证研究节点隔离，不是MINCO执行失效后的连续回退。

所有控制仍原FOLLOW，故真正MINCO回退次数为未执行，而非“零失败”；实际新轨迹激活数0。失锁/过期/任务/时钟/模式变化由纯协议测试覆盖，没有在未获准接管状态下强行飞故障场景。实际OFFBOARD/armed和锁定序列、搜索/恢复诊断保留，见supplemental_metrics。没有Y、接触截获或capture验证，本轮不评价这些成功率。

三轮Gazebo监测器退出出现pybind abort，保存monitor.txt并标记异常；采集窗口、JSONL完整性和owned进程清理另有独立证据，不能将其混成“所有进程干净退出”。修复后隔离140clock样本测试退出0，但没有重跑全飞行；原ULog/CSV/JSONL不改写。

## 复现与证据限制

离线使用p4_follow_replay.py（全部请求和自生成滚动）、p4_bounds_benchmark.py（相同输入相同系数对照）、p4_follow_analysis.py（原实际控制与纯研究分层）。历史输入SHA核验，新增产物只写本轮目录；保留优化前算法快照与最终源文件快照。三轮现场没有独立冻结完整未提交工作树：最终快照含之后编码、数值防护和监测清理修复，不能冒称现场完整源码SHA。基线HEAD、配置、原控制方法AST和各次修复记录可核查；此证据缺口限制逐字节重现现场附加节点。

现场命令/配置/环境在各轮launcher.txt、environment.json、config/、watchdog_end.json，ULog和terminal_*日志保留。自动运行脚本只能在预检无外部仿真/串口/端口占用时新建有界会话，仅清理本轮leader PID/PGID/start及明确子节点；无通配杀进程。

**后续可信比较需要先通过持有与桥接，再让新曲线实际运行，按相同场景/参考/稳定窗口独立重复，记录实际目标运动和初始化/负载差异。** 当前没有可主张的实际MINCO优于原FOLLOW结果。
