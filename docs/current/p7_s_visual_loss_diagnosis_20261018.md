# 变速 S 捕获前视觉丢失：离线归因

直接原因已经明确：**目标球体从固定前视相机的画面下边缘完全移出。近场接近没有守住可见性，失锁保护随后正确兜底。** 此前把本轮判为半径捕获/恢复接口通过，不能据此认为末端接近控制没有问题。

本次只分析既有 `20261018_p7_variable_s_full_validation_01`，未启动新仿真、未修改在线代码、模型、配置或冻结原件。新证据、脚本、CSV、图和 SHA256 位于[独立诊断目录](../../data/experiments/20261018_p7_s_visual_loss_diagnosis_01/)。

## 1. 图像在哪里消失

原相机为 640×480、水平 FOV 1.74 rad、垂直半视角约 41.6°；安装俯角 28°、相对机体原点 FLU 平移 `(0.18, 0, 0.39)` m。使用本轮保存的 SDF、完整四元数姿态和原始图像时刻复算。

| 图像原始仿真戳 | 实际红色像素 | 球体相对画面下边界的有符号余量 |
|---|---:|---:|
| 55.400 s | 33251 | +123.4 mm |
| 55.452 s | 22943 | +84.3 mm |
| 55.500 s | 15567 | +58.7 mm |
| 55.552 s | 4293 | +22.1 mm |
| 55.600 s | 0 | −1.6 mm |
| 55.652 s | 0 | −35.5 mm |
| 55.700 s | 0 | −56.5 mm |
| 55.752 s | 0 | −87.8 mm |
| 55.800 s | 0 | −107.3 mm |

这里检查的是整个球体是否还能与矩形图像相交，不能只检查球心。相机 FLU 中 +X 向前、+Z 向上，画面下边界平面为 `Z + kX = 0`，`k = height/(2fy)`。半径 R 的球体余量为：

`M = (Z + kX)/sqrt(1+k²) + R`

`M < 0` 表示整个球体已落在该边界之外。独立的 640×480 像素射线与球面求交复算也得到：5 张无效图像均为 **0 个可见交点**，与实际 0 红色像素一致。关闭 0.05 m 近裁剪后交点数仍为 0；计算不含无人机遮挡，因此出画本身足以解释这段完全丢失，不需要假设 KF 或 DDS 故障。部分可见阶段的像素数量仍可能受网格、着色、遮挡和采样影响，不把几何占据预测冒充原始 RGB 图片。

最后有效帧拟合球心约为相机 FLU `(0.116, -0.115, -0.405)` m。球心早已低于画面，仍靠球体上缘的 4293 个像素维持检测；随后连上缘也离开画面。垂直归一化图像误差 3.497 不等于目标仍安全居中。

## 2. 前次几何归因为何不明确

前次只用了较宽松的圆锥角度充分条件；这不是实际矩形传感器的下边界平面。此外，目标由 `GazeboTargetVisualizer._set_pose()` 离散移动，在目标位姿样本之间做线性插值，会构造出图像时刻未实际显示的位置。不能把下一次目标位姿提前用于该图像。

本次保留无人机原生位姿 50 ms 内的连续插值和完整姿态，目标使用图像时刻或之前最近的原生位姿。没有拟合时间偏移、扩大 bracket 或引入在线真值校正。所分析可见帧的球心复算残差 p95 从旧线性方法约 **0.1297 m** 降为 **0.00173 m**；第一张无效图像 55.600 s 更有同戳原生目标/无人机位姿。后续无效帧越界达 35–107 mm，支持连续出画的解释。

这是对先前**离线归因方法**的修正，不据此认定在线 localizer 使用了错误的目标真值插值。旧分析文件按字节保留，新结果在独立目录。

## 3. 接近控制为什么没有挡住出画

实际运动表明：首次无效图像附近，无人机高度约 **0.382 m**，与 USV 参考点的水平距离约 **0.291 m**，仍以约 **0.583 m/s** 闭合。前视相机本身又高于机体原点 0.39 m，并前移 0.18 m；接近到目标近乎位于机体下方时，目标相对相机迅速向下、向后移动。相机只有固定安装俯角，当前 IBVS 主要控制 yaw，不能用 yaw 把下方目标重新移回垂直视场。

垂直图像保护并未完全缺席。`error_v > 0.7` 后，控制确实请求减小闭合、必要时后退，但本轮开始触发保护距离首次无效图像只有约 **0.423 s**；真实闭合速度没有及时降至零，水平距离继续小于请求的约 0.40 m 终端间距。图像保护是受限速度请求，未与真实制动距离及可见性余量组成硬约束。

代码层面有一个明确缺口：`P7VisualGuidance.step()` 的 1 m 内 `CAPTURE_MATCH` 使用 `velocity_gain * (desired - previous_command)` 更新水平速度，反馈比较的是上一条命令。该分支没有直接使用实测相对闭合速度制动；`png_los()` 在小于 1 m 时返回的 `closing_speed=0` 也是禁用近零范围 PN 时的占位值，不能解释成实际已经零闭合。

独立调用当前生产代码的[受控离线探针](../../data/experiments/20261018_p7_s_visual_loss_diagnosis_01/check_nearfield_feedback.json)验证了这个行为：在上一条命令 3.0 m/s、目标 3.0 m/s、距离 0.5 m、垂直图像误差 1.0 的相同条件下，把无人机实测速度从 3.0 改为 4.2 m/s，即实际闭合从 0 改为 1.2 m/s，下一条速度命令仍完全相同，均为 2.9892 m/s。这证明分支对真实速度差没有直接反应；探针不是完整飞行或修复效果证明。

完整姿态已计入。失画时实际光轴向下约 24.6°；同位置、同航向、只在离线去掉机体 roll/pitch 的对照仍落在画面下边界之外。因此不能把原因简单归于某个 yaw 偏置或仅靠固定机身姿态解决。

## 4. 可以排除什么，修复应针对什么

- 无效帧 RGB/深度采集戳一致，接收年龄约 17–30 ms，图像仍在新鲜到达；此前有效帧的有效深度比例为 1.0。直接触发发生在原图像红色目标消失，证据不支持先调 KF Q/R 或放宽时间门槛。
- 五帧均在无近裁剪、无机体遮挡的模型中没有像素交点，出画足以解释全丢失；不需要先改相机近裁剪或模型来掩盖末端接近问题。
- 失锁后的制动、爬升和纯速度接口正确，但只能算兜底，不能补回持续视觉制导的资格。

后续修复重点应是**近场真实相对速度反馈、视场边界前的提前制动，以及下降/水平闭合的协调**。应先用本轮的独立反例验证，再做有界 S 型完整复测；不放宽半径、锁定或时效，不在失锁后继续使用失效图像。直接把整个控制误差改为实测速度并不等于已证明能捕获，仍须独立验证动作与约束。

本次已通过 7 个独立已知几何/裁剪边界检查及当前 74 项相机几何测试；生产代码探针也通过其明确数值断言。分析图见[视觉丢失时序](../../data/experiments/20261018_p7_s_visual_loss_diagnosis_01/visual_loss.png)。本报告定位原因并给出修复边界，未声称已经修改控制或验证修复成功。
