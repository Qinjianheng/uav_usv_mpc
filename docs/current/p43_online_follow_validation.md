# P4.3 在线影子与原FOLLOW验证

## 结论

本轮真实PX4/Gazebo始终由原FOLLOW控制，MINCO实际接管**未执行**。同参数H1.2的修复后完整影子对照：P4.1合法发布周期P95=69.60ms，P4.3固定候选=60.80ms，降低12.65%；全部完成周期P95降低7.94%。**20%提速目标未达到**，保留原始失败周期和统计口径，没有用早停数据、跳过验收或只挑最短周期宣称达标。

共同初始化的F3理想滚动稳态小于1m已实现，但旧P4.1的H1.6也能达到约0.505m，不能归为全新的算法突破。P4.3 H1.6固定候选约0.505m，Q/QT改善全程而削弱稳态；未证明真实MINCO闭环优于原FOLLOW。推荐继续显式影子研究3/1、H1.6、refinement=none，保留现有默认H1.2。

## 实验与失败保护

基点97c8c8c；`flights/`按A→G完成13个独立场景/重复，`flights_profile_fixed/`重跑8个受影响影子条件，共22次隔离SITL（含一次记录器异常退出的有界复验）。每次X后80s，watchdog300s，最多一次启动重试、独立DDS domain/GZ partition，只清理PID/PGID/start匹配的自有进程。每轮保留配置、源码快照、Git SHA、完整日志、原生Gazebo/ROS数据、PX4 ULog、CPU/RSS和清理记录。

首批8个影子轮出现新profiling代码对拒绝结果缺少metrics的KeyError，planner提前退出，原FOLLOW仍运行。全部原始记录保留，标记`planner_runtime_error=true`，**排除其规划延迟作为最终证据**。最后G/Q/H1.6轮记录器在清理时以-6退出，完整原记录保留；会话成功判定新增monitor_returncode和残留进程检查，并仅做一次有界复验。复现测试RED→GREEN，完成前拒绝与父类发布期间替换输出均覆盖；修复后8轮完整重跑。会话脚本的FOLLOW_WINDOW_COMPLETE仅说明飞行窗口结束，不自动等于planner全程健康。

源码freeze在launcher Popen之前执行，清单包括配置/资源/消息等所有普通源码文件，已修复只按后缀挑选造成setup.cfg缺失的问题。不同轮源码有独立SHA，测量producer日志为opt-in；不能把早期未记录的BCTRA子调用补造为已测量。
